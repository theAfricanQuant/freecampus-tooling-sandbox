The tools, in plain English

Conda: sets up the workspace

Think of Conda as setting up a classroom before a lesson. It gives us Python and larger tools such as Quarto and Jupyter. The shopping list is environment.yml.

Poetry: keeps the Python list

Poetry installs Python add-ons and records their versions. pyproject.toml describes the project; poetry.lock records the exact versions chosen.

Jupyter: the exercise book

A notebook mixes notes and Python code cells. We saved ours as notebooks/tooling-lab.ipynb.

Quarto: the publisher

Quarto takes the notebook and makes an HTML page from it. When asked, it also runs the notebook cells through Python.

Makim: the task organiser

Makim reads .makim.yaml and gives commands short, memorable names. It starts the right tool for each task.

Git: the project history book

Git records the files and changes, so we can keep the working Stage 1 setup as a checkpoint before trying Stage 2.

What happens when we render?

First, we name the job: lab.render. Makim looks up that job in .makim.yaml, then starts the command written there. Quarto uses Python and Jupyter to run the notebook cells and makes the finished HTML lesson.

One more Nigerian picture: Conda sets up the market stall with the main tools, and Poetry keeps the written list of Python add-ons and versions. Makim is the park marshal; it sends the job to Quarto, but it does not drive the danfo or run the notebook code itself.

The full command saved in Makim is:

quarto render notebooks/tooling-lab.ipynb --to html --execute

We type a task name instead of remembering that whole command. The --execute part tells Quarto to run the notebook cells while rendering. Without it, Quarto expects the notebook to have already been run and saved.

Problems we hit and how we fixed them

We built the setup one step at a time. These problems helped us learn which tool was responsible and what it needed.

  1. The folder was empty and was not a Git repo. Git could not show a branch or remote yet. We cloned the GitHub repo into the folder, then created the Stage 1 branch.
  2. Conda was not found after installation. We chose not to let the installer edit the shell profile. We loaded Conda's shell hook in the current terminal; a new terminal needs the hook again unless we choose to initialize the shell later.
  3. Poetry saw Python 3.13 instead of the required 3.12. The old VIRTUAL_ENV setting pointed at another virtual environment. We used env -u VIRTUAL_ENV for the Poetry command so it could use the Conda Python 3.12 environment.
  4. There were no project setup files to start from. We wrote environment.yml, pyproject.toml and .makim.yaml ourselves in Neovim. That made each file's purpose visible instead of hiding it behind a setup wizard.
  5. Poetry refreshed packages already in the Conda environment. The install showed many package updates. It completed successfully, but it also showed that Poetry and Conda were working in the same environment during this experiment.
  6. Makim first stopped with “No module named click”. Makim needed the Python package click, but it was missing from the project's install. We added it to pyproject.toml, refreshed the lock file, and installed again.
  7. Makim first said its config file was missing. It looks for .makim.yaml by default. We created that file and added the lab.hello and lab.render tasks.
  8. YAML treated punctuation in a command as special syntax. We quoted the full echo command in the YAML file so its colon was read as part of the text.
  9. quarto update asked us for an extension. That command is for updating a Quarto extension, not a general software updater. We used Quarto's version and render commands for this lab instead.
  10. Our first search did not find the notebook's greeting. The code had not yet been saved in the notebook file. We saved the notebook and checked tooling-lab.ipynb again.
  11. The first HTML page did not show fresh cell output. Quarto had not been told to execute the notebook. Adding --execute made it run the cells before writing HTML.
  12. Generated files appeared as untracked Git files. Jupyter checkpoints and Quarto's HTML and supporting files are build output. We added ignore rules so they do not clutter normal Git status.
  13. Xonsh printed a deprecation warning. Makim selected Xonsh as its shell and one old setting was deprecated. The warning did not stop either task; both Makim commands completed.

What difference did Makim make?

Without Makim, we would type the long Quarto command ourselves. With Makim, the command has a name: lab.render. The task is written down once, so we can run it again later or share it with another learner.

Makim helps with repeatable tasks

  • Run the notebook or build course pages.
  • Run checks and tests before sharing changes.
  • Format or check code with tools such as Ruff.
  • Preview lessons or documentation on a laptop.
  • Clean generated files when we want a fresh build.

Those are ideas for future tasks. In Stage 1, we made lab.hello and lab.render.

The full Makim file, explained line by line

This is the whole .makim.yaml file we made. It gives two commands short names. 

groups:
  lab:
    tasks:
      hello:
        help: Confirm Makim runs in Stage 1
        run: 'echo "Stage 1: Conda + Poetry + Makim"'
      render:
        help: Render the Jupyter notebook to HTML with Quarto
        run: quarto render notebooks/tooling-lab.ipynb --to html --execute
  1. groups: tells Makim that task groups follow.
  2. lab: names our group. It becomes the first part of a task name.
  3. tasks: starts the list of commands Makim can run.
  4. hello: names the first task. Together, the group and task make lab.hello.
  5. help: is the short explanation shown in Makim's help screen.
  6. run: tells Makim what shell command to run. Here, echo prints a message.
  7. render: names the second task. Together with lab, it becomes lab.render.
  8. The second help: describes the render task in the help screen.
  9. The second run: starts Quarto. render means make an output file; the notebook path is the input; --to html chooses a web page; --execute tells Quarto to run the Python cells first.

The command we typed

env -u VIRTUAL_ENV poetry run makim lab.render
  • env -u VIRTUAL_ENV hides the old Python environment setting for this one command.
  • poetry run starts the next command in the environment Poetry is using.
  • makim starts the task runner.
  • lab.render asks it to run the render task in the lab group.

The full command is used because this computer had an old environment setting pointing to Python 3.13. In this Stage 1 setup, removing that setting lets Poetry use the Conda environment with Python 3.12.

What Makim does not do

Makim does not install Python, manage package versions, or write notebook lessons. Conda and Poetry set up the tools and packages. Jupyter runs code cells. Quarto renders the notebook. Makim coordinates the commands.

The notebook is stored on GitHub, and the link above opens it in Google Colab. The rendered HTML file is a separate web page.
